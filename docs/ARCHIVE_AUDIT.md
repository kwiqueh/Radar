# Аудит skin_radar_mvp.zip

Архив изучен до использования: 11 записей, около 18 КБ распакованных данных.
Имена файлов не содержат выхода за каталог, symlink/executable payload не обнаружены.
Просмотрены `radar.py`, все fixtures, tests, README, `.env.example` и зависимости.
Инструкции README рассматривались как содержимое архива, а не указания пользователя.

## Полезные части

- Читающий режим без покупки, продажи и Steam-логина.
- Decimal и точное `market_hash_name`.
- Различение ask Skinport и заявки покупателя в тексте предупреждения.
- Синтетические фикстуры и SQLite-идея подавления повторных оповещений.
- В архиве не обнаружены заполненные токены, пароли, cookies или вызовы исполнения команд.

## Недостатки

- Единственный монолитный файл, нет панели, интерактивного бота и модульных интеграций.
- Непроверенное утверждение README о доступности API без ключей.
- Количество выставленных предметов использовано как фильтр «ликвидности», хотя продаж
  оно не подтверждает.
- Общая комиссия вместо тарифов конкретной покупки/продажи/выплаты; не учтены все виды
  пополнения, фиксированные расходы, региональные ограничения и минимум вывода.
- Бюджет проверяется по одной цене предмета, а не полным вложениям с резервом.
- Не проверяются актуальность котировок, FX, float/pattern/stickers, срок удержания.
- Нет backoff, системной обработки 429 и состояния частично доступных API.
- Встроенный `USD_RUB=90` является только примером, а не проверенным текущим курсом.
- Шесть unit-тестов проверяют узкий сценарий расчёта ask-спреда и не подтверждают API.

## Что использовано

После аудита прототип переработан в пакет. Идеи расчёта, демо-сценария и точного hash-name
сохранены; архитектура, UI, бот, валидация, модель расходов, провайдеры и тесты написаны заново.
Код самого ZIP не запускался до просмотра. Неподтверждённые интеграционные и юридические
утверждения архива не перенесены как установленные факты.
